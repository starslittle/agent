## 0. 结论

当前前端已经是一套完成度较高的“奇点 AI 对话工具”界面，但它与启点的产品定位仍有明显偏差。

启点不是另一个更炫的 AI 聊天框，而是：

> 一个由个人 Wiki 驱动的决策副驾驶。

因此，本次改版不能只把“奇点 AI”替换成“启点”。现有的宇宙轨道、紫蓝渐变、玻璃发光和旋转“奇”字图形，共同表达的是“奇点、模型能力、通用 AI”；启点需要表达的则是“从一个问题出发，连接个人信息，形成判断并持续沉淀”。

本设计基线确定以下方向：

1. 产品主品牌统一为“启点”，助手称为“启点助手”，不使用“启点 AI”作为默认产品名。
2. 视觉风格从“宇宙科技感”转为“安静、可信、可长期阅读的个人工作空间”。
3. 用一套独有的“启点线”表达从起点到上下文、分析、决定和复盘的连续过程。
4. 保留当前清晰的对话骨架、深浅色模式和运行过程展示，重做品牌表达与产品信息架构。
5. 页面能力随业务 Round 渐进出现，不展示尚不可用的 Wiki、Decision 或 Skill 入口。

## 1. 设计依据

### 1.1 产品文档

本文以以下产品基线为准：

- [`启点 Web MVP 产品需求`](../product/web-mvp.md)：完整 Web 产品包含对话、Wiki、决策、进化收件箱、Runs 与 Skills。

- [`业务交付轮次`](../../collaboration/rounds/README.md)：前端能力必须跟随 ROUND-01～04 的真实可用范围逐步开放。

## 2. 用户与核心任务

### 2.1 当前用户

当前首先服务产品创建者本人，主要任务包括：

- 记录和维护个人背景、状态、规则与经历；
- 基于个人上下文分析面试、职业、项目和生活选择；
- 导入面试复盘等 Markdown；
- 使用 Decision、Fortune 等不同 Skill；
- 查看 Agent 真实使用了哪些上下文、工具和步骤；
- 确认或拒绝 AI 提出的长期信息更新。

### 2.2 页面必须回答的三个问题

无论处于哪一个业务 Round，主界面都应尽量让用户快速知道：

1. 我现在可以让启点做什么？
2. 启点这次为什么给出这个回答？
3. 这次对话会不会改变我的个人信息或决策记录？

## 3. 品牌系统

### 3.1 品牌命名

| 场景 | 推荐用语 | 不推荐 |
| --- | --- | --- |
| 产品名 | 启点 | 启点 AI、奇点 AI |
| 助手名 | 启点助手 | 启点 Agent、机器人 |
| 工作空间 | 启点 | 启点工作台 Pro |
| 英文辅助字 | QIDIAN | QIDIAN INTELLIGENCE |
| 核心定位 | 个人 AI Wiki 与决策副驾驶 | 智能体对话前端 |

产品名不默认带“AI”，原因是启点的核心资产是用户拥有的个人 Wiki、决策和历史，不是某一个模型。

### 3.2 核心文案

主定位：

> 个人 AI Wiki 与决策副驾驶

主价值表达：

> 让 AI 真正了解你的信息，再和你一起做决定。

解释性文案：

> 从眼前的问题开始，启点会结合你确认过的信息，陪你分析、记录并复盘。

### 3.3 品牌记忆点：启点线

“启点线”是整套产品唯一需要明显表达个性的视觉母题。

```text
●────────○──────○────────●
起点      个人信息   分析过程      决定 / 更新
```

构成原则：

- 起点是一个暖珊瑚色实心点；
- 主路径是一条克制的松绿色细线；
- 路径中的空心节点代表待确认信息、工具步骤或中间判断；
- 终点只有在任务完成或用户确认后变为实心；
- 线条可以轻微转折，但不画成宇宙轨道、神经网络或无限发光粒子。

可复用位置：

- 品牌图形和 favicon；
- 登录页主视觉；
- 空白对话页；
- Agent Run 时间线；
- Wiki Revision；
- Decision 分析与复盘；
- AI 更新 Proposal 的确认过程。

### 3.4 Logo 使用建议

首版不需要复杂插画。可使用“起点 + 向右展开的两段路径”构成抽象字标，旁边显示“启点”。

```text
●╴╴┐  启点
   └○
```

约束：

- 不再使用单独的“奇”字作为头像或品牌图形；
- 不使用旋转圆环；
- 不依赖渐变才能被识别；
- 16×16 favicon 下仍可看见一个起点和一个方向；
- 最终矢量造型在首版视觉实现后再定稿，本文只固定概念。

## 4. 视觉设计系统

### 4.1 视觉气质

关键词：

- 安静；
- 可信；
- 私人；
- 长期可阅读；
- 有过程、有依据；
- 温和但不软弱。

避免：

- 通用 AI 紫蓝渐变；
- 大面积玻璃拟态和辉光；
- 宇宙、星球、轨道、粒子；
- 每张卡片都圆角、悬浮、发光；
- 用装饰性仪表盘制造“Agent 很复杂”的感觉；
- 营销 Landing Page 风格侵入日常工作区。
- “暖色纸张 + 大号衬线 + 陶土色”的常见 AI 生成设计组合。
- 用网格背景、编号卡片和大量胶囊标签证明产品“有设计”。

### 4.2 色彩

#### 浅色模式

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#FAFAF8` | 中性偏暖页面底色 |
| `surface` | `#FFFFFF` | 对话、表单、主要内容面 |
| `surface-muted` | `#F2F3F1` | 侧栏、次级区域 |
| `ink` | `#1D2421` | 主文字 |
| `muted` | `#6C736F` | 次级文字 |
| `primary` | `#356658` | 主操作、选中态、路径线 |
| `primary-hover` | `#2C564A` | 主操作悬停 |
| `start` | `#C76B42` | 启点、提醒、关键转折 |
| `border` | `#E1E5E2` | 普通边界 |
| `danger` | `#B9473D` | 删除与错误 |

#### 深色模式

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#111412` | 页面底色 |
| `surface` | `#171A18` | 主要内容面 |
| `surface-muted` | `#1C201D` | 侧栏、次级区域 |
| `ink` | `#E7EBE8` | 主文字 |
| `muted` | `#989F9A` | 次级文字 |
| `primary` | `#83B3A4` | 主操作、选中态、路径线 |
| `start` | `#DC8A63` | 启点与关键转折 |
| `border` | `#2B302D` | 普通边界 |
| `danger` | `#E07A70` | 删除与错误 |

使用原则：

- 珊瑚色只用于“开始、变化、需要用户注意”的少量位置，不作为整页 CTA 色；
- 松绿色承担主要交互状态和结构路径；
- 长文本保持高对比，正文对比度至少达到 4.5:1；
- 状态不能只靠颜色表达，必须同时有文字或图标。

### 4.3 字体

| 内容 | 字体建议 |
| --- | --- |
| 正文、操作、表单 | `PingFang SC`、`Noto Sans SC`、系统无衬线 |
| 品牌名、一级标题 | 同一系统无衬线字体，以字重和间距区分 |
| Run ID、时间、技术字段 | `ui-monospace` |

原则：

- 不额外加载展示型衬线字体，避免把回答包装成营销海报或 AI 生成的编辑风页面；
- 品牌名使用约 18px、700 字重，回答结论控制在 21～27px；
- 数字对齐场景使用 `font-variant-numeric: tabular-nums`；
- 标题使用紧凑字距，正文保持舒展行高；
- 优先使用系统字体；若加载 Web Font，需预加载关键字重并使用 `font-display: swap`。

### 4.4 圆角、边界与阴影

| 类型 | 建议 |
| --- | --- |
| 小控件 | 8px |
| 输入框、按钮 | 10～12px |
| 内容卡片 | 14～16px |
| 大容器 | 不超过 20px |
| 普通阴影 | 尽量不用，以 1px 边界和底色分层 |
| 浮层阴影 | 低饱和、短距离、只用于菜单和对话框 |

不要让所有元素都成为“胶囊”。状态标签可以使用全圆角，主按钮和输入框保持明确边界。

### 4.5 动效

动效强度设为低：

- 页面进入：150～220ms 的透明度与 4～8px 位移；
- Skill 菜单和 Proposal 展开：160～200ms；
- 启点线运行态：节点依次点亮，不使用无限旋转；
- 只动画 `transform` 和 `opacity`；
- 所有非必要动效遵守 `prefers-reduced-motion`；
- 用户点击停止后，运行态动画立即停止，不能等待当前循环结束。

## 5. 信息架构

### 5.1 长期结构

```text
启点
├── 对话
├── 我的 Wiki
├── 决策与复盘
├── 进化收件箱
├── Agent Runs
└── Skills
```

这是完整 Web MVP 的长期结构，不代表所有入口需要立刻显示。

### 5.2 按 Round 渐进出现

| Round | 可见主导航 | 不应提前展示 |
| --- | --- | --- |
| ROUND-01 | 对话 | Wiki、Decision、Skills、空壳 Runs |
| ROUND-02 | 对话、Agent Runs | 尚未 available 的 Decision Skill、Wiki |
| ROUND-03 | 对话、我的 Wiki、Agent Runs | 尚未实现的决策与复盘 |
| ROUND-04 | 对话、我的 Wiki、决策与复盘、Agent Runs | 未实现的进化收件箱与完整 Skills 管理 |

原则：

- 不做不可点击的“即将上线”主导航；
- Skills 不作为永久一级入口来替代自然语言；
- `/` 菜单只显示后端实际标记为 available 的 Skill；
- 同一个统一助手承载普通聊天、检索和专业 Skill。

## 6. 页面设计

### 6.1 登录 / 注册页

目标：先建立“这是一个私人、长期、可信的工作空间”，而不是展示模型技术感。

桌面结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ ●──○  启点                                      个人 AI Wiki │
│                                                              │
│            让 AI 真正了解你的信息，                          │
│            再和你一起做决定。                                │
│                                                              │
│            ┌──────────────────────────────┐                  │
│            │ 欢迎回来                     │                  │
│            │ 邮箱                         │                  │
│            │ 密码                         │                  │
│            │          登录                │                  │
│            └──────────────────────────────┘                  │
│            登录后继续你的对话、Wiki 与决策记录。             │
└──────────────────────────────────────────────────────────────┘
```

文案：

- 品牌：`启点`
- 辅助定位：`个人 AI Wiki 与决策副驾驶`
- 主标题：`让 AI 真正了解你的信息，再和你一起做决定。`
- 登录说明：`登录后继续你的对话、个人 Wiki 与决策记录。`
- 注册说明：`从眼前的问题开始，逐步建立属于你的个人 Wiki。`

视觉：

- 背景使用矿物白，不放大面积发光光斑；
- 以静态“启点线”作为唯一主视觉；
- 表单保持单列，最大宽度约 440px；
- 移动端不自动聚焦，避免键盘遮挡页面。

### 6.2 应用外壳

桌面结构：

```text
┌──────────────────┬───────────────────────────────────────────┐
│ ●──○  启点       │ 对话标题                     主题 / 账户   │
│                  ├───────────────────────────────────────────┤
│ ＋ 新建对话      │                                           │
│                  │              当前页面内容                 │
│ 对话             │                                           │
│ Agent Runs       │                                           │
│ 我的 Wiki        │                                           │
│ 决策与复盘       │                                           │
│                  │                                           │
│ 最近对话         │                                           │
│ ……               │                                           │
│                  │                                           │
│ 搜索             │                                           │
└──────────────────┴───────────────────────────────────────────┘
```

要求：

- 主导航和最近对话分组明确；
- 导航使用真正的链接，保证 Cmd/Ctrl + 点击和深链；
- 移动端侧栏变为 Drawer，并处理安全区；
- 页面使用 `100dvh`，避免移动浏览器地址栏造成高度错误；
- “在线”只有连接到真实运行状态时显示，否则移除。

### 6.3 对话空白页

目标：用三个真实任务告诉用户启点能做什么，不展示一排永久 Skill 按钮。

```text
                         ●────○

                      启点助手
                今天想从哪个问题开始？

       告诉启点你正在面对什么。它会结合你确认过的
       信息，和你一起分析、记录并复盘。

       ┌────────────────┐ ┌────────────────┐ ┌────────────────┐
       │ 分析一个决定   │ │ 导入面试复盘   │ │ 进行命理分析   │
       │ 梳理选项与代价 │ │ 提取可用信息   │ │ 使用命理 Skill │
       └────────────────┘ └────────────────┘ └────────────────┘

       ┌───────────────────────────────────────────────────────┐
       │ 描述你想解决的问题…                              发送 │
       │ / 选择 Skill                                ⌘/Ctrl K │
       └───────────────────────────────────────────────────────┘
```

快捷卡片：

| 标题 | 默认 Prompt |
| --- | --- |
| 分析一个决定 | `我正在面对一个选择，帮我梳理选项、约束和需要补充的信息。` |
| 导入面试复盘 | 打开真实 Markdown 导入流程；功能未完成前不展示 |
| 进行命理分析 | `/fortune 我想从命理视角分析一个问题。` |

ROUND-02 时如果 Markdown 导入尚不可用，第二张卡片应换成真实可用的“研究一个问题”，不能制造假入口。

### 6.4 输入区与 Skill

当前永久“深度思考”开关不符合统一助手架构。用户不应该先理解底层链路，再决定使用“普通模式”还是“深度模式”。

目标交互：

```text
┌───────────────────────────────────────────────────────┐
│ 描述你想解决的问题…                                   │
│                                                       │
│ / 选择 Skill     [决策 Skill ×]    已使用 4 条上下文  │
└───────────────────────────────────────────────────────┘
```

规则：

- 默认直接自然语言输入；
- 输入 `/` 后展示 available Skills；
- 用户显式选择时显示可移除标签；
- 自动路由时，生成开始后在回答顶部标明所选 Skill；
- 路由低置信度时退回普通聊天；
- “深度”属于 Agent 内部预算和策略，不作为长期产品模式；
- 附件按钮只有在真实上传、预览、失败处理和删除都完成后才显示。

### 6.5 助手回答

回答分为三个层次：

```text
启点助手
[决策 Skill] 自动选择 · 使用 4 条个人信息 · 调用 1 个工具

最终回答正文……

────────────────────────────────────────
查看分析过程    查看使用的个人信息    查看 Agent Run

启点建议更新 2 条个人信息
[查看并确认]
```

显示原则：

- 正文始终是视觉主角；
- Skill、上下文和工具信息可见，但不抢占正文；
- Activity 和最终回答继续分层；
- AI 分析不得伪装成用户已确认事实；
- 写入 Wiki 前必须出现可确认的 Proposal；
- 失败应说明发生了什么、哪些结果仍然有效、用户下一步能做什么。

### 6.6 Agent Runs

用户 Runs 页面不是内部运维后台。它回答“我的这次任务发生了什么”。

建议结构：

```text
● 接收问题
│  普通对话 → 决策 Skill
○ 读取个人上下文
│  4 条，点击可查看
○ 调用工具
│  research.search · 已完成
● 生成回答
   18.4s · completed
```

要求：

- 延续“启点线”视觉；
- 清楚区分 queued、running、completed、failed、cancelled、timed_out；
- 提供对应会话的返回入口；
- 技术字段放在次级详情中；
- 内部观测后台与用户 Runs 共用事件和数据语义，但使用不同权限与界面密度。

### 6.7 我的 Wiki

ROUND-03 才出现。页面优先表达信息的来源、类型、状态和修改历史，而不是做成普通笔记应用。

每条信息至少可识别：

- 已确认事实 / 当前状态 / 个人规则 / AI 分析 / 历史记录；
- 来源；
- 生效或记录时间；
- 当前有效性；

### 6.8 决策与复盘

ROUND-04 才出现。页面结构围绕真实决策，而不是围绕模型回复：

```text

→ 用户最终选择

```

## 13. 设计原则摘要

后续做任何页面时，都用以下顺序判断：

1. 先确认它是否支持用户的个人信息与决策闭环；
2. 再确认当前 Round 是否真的可用；
3. 然后保证依据、状态和写入影响可见；
4. 最后才增加视觉表现；
5. 如果装饰不能帮助理解“从问题到沉淀”的过程，就删除它。

一句话设计方向：

> 启点应该像一张会理解用户、留下依据并持续生长的个人工作台，而不是一个会发光的聊天机器人。

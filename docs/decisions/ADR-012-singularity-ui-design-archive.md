# ADR-012：奇点 AI 只作为设计档案保留

> 状态：accepted
>
> 日期：2026-07-31

## 背景

当前正式前端仍使用“奇点 AI”的品牌、紫蓝配色、轨道图形和通用 AI 对话产品表达。
产品后续将迁移为“启点”，定位是个人 AI Wiki 与决策副驾驶。

讨论过同时保留两套可运行 UI，或者让两套品牌共享同一组业务能力。用户最终确认：

> 奇点 AI 只需要作为设计档案保留，不作为后续运行模式，也不继续维护。

## 决策

### 1. 启点是唯一正式演进方向

后续前端实现、业务能力、响应式适配、可访问性修复和 E2E 只面向启点。

不新增：

- `singularity` / `qidian` 运行时切换；
- `VITE_UI_VARIANT` 等双品牌构建变量；
- `/legacy` 或类似旧版页面入口；
- 两套 Shell、Design Token 或品牌组件；
- 为奇点 AI 新增的回归测试和兼容逻辑。

### 2. 奇点 AI 使用 Git 基线归档

奇点 AI 最终源代码基线为：

```text
commit: 8d00829
tag: design/singularity-ai-archive
```

该提交中的 `frontend/` 是启点视觉迁移前的奇点 AI 前端。Tag 只用于历史查看和临时
恢复，不代表可部署版本或长期支持分支。

如果未来需要查看原界面，可以从 Tag 创建临时 worktree 或读取对应文件；不把旧代码
复制到当前前端目录、归档目录或新的应用中。

### 3. 设计档案记录

奇点 AI 的设计说明见
[`奇点 AI 设计档案`](../design/archive/singularity-ai.md)。

启点的新视觉方向见
[`启点 Web 视觉与交互设计基线`](../design/qidian-web-visual-ux-spec.md) 和独立 HTML
概念稿。概念稿用于确定色调和交互气质，不代表当前 Round 必须一次实现其中展示的
全部业务模块。

## 原因

- 保留从通用 AI 对话工具到个人 Wiki 与决策 Agent 的产品演进证据；
- 避免双 UI 导致实现、测试和维护成本长期增加；
- 避免旧品牌限制启点的信息架构与交互设计；
- Git 基线已经能够完整保存源码，不需要在仓库中复制一份废弃代码；
- 需要查看时仍能可重复地恢复原始设计。

## 后果

正面：

- 启点只有一套产品和视觉事实来源；
- 后续 Task 不需要兼容旧品牌；
- 旧版仍可通过 Tag 查看；
- 面试或项目复盘时可以展示产品演进。

代价：

- 奇点 AI 不会获得新业务能力、缺陷修复或浏览器适配；
- Tag 中的旧版是否能直接运行，取决于当时的依赖和环境；
- 如需高保真历史截图，应从 Tag 临时启动后单独采集。

## 约束

- 不把奇点 AI 重新加入产品导航、Feature Flag 或正式发布流程；
- 不为保留档案复制完整 `frontend/`；
- 启点实现可以自由修改或删除当前奇点 AI 组件；
- 删除或重写旧界面前，必须保证 `design/singularity-ai-archive` Tag 已经推送远程；
- 本 ADR 不授权提前实施启点正式前端，仍需遵守业务 Round 与 Task 边界。

# ADR-014：ROUND-03 使用递归个人空间与只读 Skill 目录

> 状态：accepted
>
> 日期：2026-08-01

## 背景

原 ROUND-03 以“我的 Wiki”扁平列表和单篇 Markdown 导入为中心。用户进一步确认，
这个心智不适合作为长期产品入口：个人内容会持续增加，也会从 Obsidian 等目录中整批
导入；如果顶层同时平铺文件夹、全部文档、最近打开和结构化事实，页面会很快失去层级，
用户也无法像管理本地文件一样理解当前位置。

同时，Skill 是用户理解“启点怎样工作”的重要入口。现有对话中的 `/` 选择只适合
触发，不适合查看 Skill 内容、数据范围和确认规则；但当前又没有成熟的草稿、校验、
测试、发布、版本与回滚协议，直接提供编辑会制造错误预期和安全风险。

## 决策

### 1. 用户入口命名为“我的空间”

“我的空间”是用户文档与个人上下文的统一产品入口，但不是第二套事实源：

- PostgreSQL 中的确认事实、状态、规则、来源与 Revision 仍由 Go 拥有；
- Markdown Document 是用户可携带的开放文档；
- 用户界面以文件夹和文档为主，结构化上下文作为文档提取、Proposal、Run 和详情中的
  可追溯索引，不再与文档竞争一个扁平一级列表；
- 凡是会长期影响回答的结构化信息仍必须可查看、修改、暂时遗忘、恢复和永久删除。

### 2. 空间使用递归目录模型

根路由只展示当前目录的直接子项。文件夹可以继续包含文件夹和 Markdown 文档：

```text
/space
→ /space/folders/:folderId
→ /space/folders/:childFolderId
→ /space/documents/:documentId
```

产品行为固定为：

- 根页展示顶层文件夹，不增加“最近打开”专区或全库文档表；
- 文件夹页展示当前目录的直接子文件夹和直接子文档；
- 面包屑、浏览器前进/后退、刷新和深链接保持当前位置；
- 当前目录可按最近打开或名称 A–Z 排序，文件夹始终排在文件前；
- 文档阅读页保留 256px 一级工作区侧栏，桌面端增加单个上下文浏览栏，主要面积留给
  文档正文；移动端改为抽屉或分层路由，不制造横向溢出；
- 大目录必须分页、虚拟化或使用等价的有界渲染策略。

### 3. 文件夹导入是 ROUND-03 基础能力

用户可以选择一个包含嵌套目录和 Markdown 的文件夹导入，系统保留安全的相对路径和
层级。单篇 `.md` 导入只是该能力的子集。

ROUND-03 不实现 Obsidian 实时同步，也不把本地绝对路径作为产品身份。重复导入、
同名冲突、部分失败、非法路径、软链接、非 Markdown 文件、大小与数量上限必须有明确
策略；导入不能把文档内容自动升级为确认事实。

### 4. Skills 提供目录和只读详情

ROUND-03 增加 `Skills` 一级入口：

- 目录只展示服务端判定为当前用户有效且可见的真实 Skill；
- 详情使用可深链接的 `/skills/:skillId`，桌面端可表现为路由化弹窗，移动端为全屏页或
  Sheet；
- 详情只展示公开投影：标题、描述、版本、用途、公开 Capability、个人上下文范围、
  确认/写入规则和“在对话中使用”；
- 不返回或渲染系统 Prompt、隐藏工作流指令、Secret、原始工具输入输出或内部禁用原因；
- 内置 Skill 不提供开关、卸载或直接编辑。

Skill Manifest 和可执行性仍由 Python Registry 拥有；Go 结合产品策略、用户权限和
Runtime readiness 输出用户可见的有效 Skill 投影。前端不得维护第二份可用性事实源。

### 5. Skill 编辑器后置

本轮不实现 Skill 内容编辑器。未来编辑必须采用独立 Skill Workbench 契约：

```text
复制/派生内置 Skill
→ 个人 Draft
→ 编辑
→ Schema 与安全校验
→ 隔离测试和 Diff
→ 发布新版本
→ 回滚
```

内置 Skill 不原地修改；没有版本、测试和回滚前，不用普通 Markdown 编辑器伪装成
可安全发布的 Skill 编辑器。

## 原因

- 目录递归能够随文件夹数量增长，而不让根页退化成无限卡片墙；
- 文件夹整体导入符合 Obsidian 和本地文件管理的既有心智；
- 文档与结构化事实分层后，用户看到的是自己的内容，系统仍保留可审计上下文；
- Skills 目录解决“看得见、看得懂、能试用”，而不提前承担编辑和发布系统的复杂度；
- 服务端公开投影避免前端静态列表与真实 Registry 漂移，也避免泄露内部指令。

## 后果

正面：

- ROUND-03 的用户入口和未来 Obsidian 导入方向一致；
- 文件夹、文件和 Skill 都具有稳定 URL，可恢复、可分享站内链接；
- “我的空间”和“Skills”分别回答“启点了解什么”和“启点怎样工作”；
- 后续 Skill Workbench 可以独立演进，不阻塞当前只读体验。

代价：

- Document 需要父目录、规范化路径、移动/重命名和冲突语义；
- 文件夹导入比单文件上传需要更严格的安全和事务设计；
- ROUND-03 增加一个跨 Python、Go 与前端的 Skill 公开投影 Task；
- 原“我的 Wiki”页面和相关验收需要调整为“我的空间 + 可追溯上下文”。

## 约束

- 本 ADR 不授权启动 ROUND-03、推送、部署或生产迁移；
- ROUND-03 仍需用户明确授权，并遵守 Solo Protocol 的逐 Task 提交和轮次唯一 E2E；
- 所有前端 Task 必须使用 `frontend-design`、`ui-ux-pro-max` 和
  `web-design-guidelines`；
- 本 ADR 只收窄 ADR-011/013 中 ROUND-03 的用户界面和任务范围，不改变业务轮次门禁、
  数据所有权或 ROUND-02 已接受基线；
- Agent 文档 CRUD、Obsidian 同步和 Skill 编辑/发布仍需要独立后续授权。
